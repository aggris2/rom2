# `.16` sprite files and the fonts

A `.16` file holds a font of one colour: a frame for each character,
whose pixels say only how solid they are. The game gives the text its
colour.

The original has three, and a fourth font in the `.16a` format:

| Font | File | Glyphs | Size of a glyph |
|---|---|---|---|
| font1 | `font1/font1.16` | 224 | 16 by 15 |
| font2 | `font2/font2.16` | 224 | 8 by 10 |
| font3 | `font3/font3.16` | 64 | 8 by 6 |
| font4 | `font4/font4.16a` | 224 | 16 by 16 |

Measured on those files of the GOG release, all in `graphics.res`.
Every glyph was read to its exact end. All numbers are unsigned 32-bit,
low byte first, unless said.

Read by `tools/import/sprite16.c`.

## Layout

A `.16` file is a `.256` file without a palette (see [256.md](256.md)):

```
frames, one after the other
count of frames, 4 bytes
```

In `font1.16` and `font2.16` more bytes follow that count: 17,712 in the
first and 28 in the second, which end in the count once more. They look
like the end of an older and longer file. Reading the count from the
last 4 bytes and the frames from the start, as for a `.256`, passes
them over.

## A frame

```
width, height, size of the codes in bytes
the codes
```

A code is one byte: its kind in the top two bits and a count in the
other six.

| Kind | Meaning |
|---|---|
| 0 | `count` bytes of pixels follow |
| 1 | skip `count` whole rows |
| 2 | skip `count` pixels, on into the next row if need be |

Kind 3 does not occur. The codes of a frame fill it exactly.

A byte of pixels is two pixels: its lower half first, then its upper
half. Each is how solid the pixel is, 1 to 15. A run of an odd number
of pixels has nothing for the upper half of its last byte, and leaves it
0: so the last byte of a run whose upper half is 0 is one pixel.

That rule cannot go wrong, by what was measured: no lower half is ever
0, and no upper half but that of a run's last byte. A pixel that is not
there is always skipped, never written.

The solidness takes few values: 4, 8, 11, 13 and 15 in font1.

## The glyphs

The frames are in the order of the characters, and the first is the
space, character 32. So font1, font2 and font4 reach character 255, and
font3 character 95.

After the letters of ASCII come accented Latin letters from character
128, in the order of the DOS code page 437, and Cyrillic letters from
192, in the order of the Windows code page 1251. font3 has little more
than the digits.

## The widths, `.dat`

Beside each font is a file of the same name that ends in `.dat`: a
number for each glyph, how wide it is in pixels. font1's are up to 14,
font2's up to 6. The space has 0 in all four, so how far a space moves
on is not in the file.

## What ROM2 writes for a font

The importer writes a folder for every font into `content/fonts`, named
as the original names it:

| File | What it is |
|---|---|
| `font.toml` | the size of a cell, the first character, the width of every glyph |
| `glyphs.png` | all the glyphs in a grid 16 across, each in the top left corner of its cell |
| `alpha.png` | for font4: how solid each pixel is |

For a font of one colour `glyphs.png` is a picture in shades of grey:
how solid each pixel is, with the file's 15 levels spread over 17 to
255. For font4 it is indices with the font's palette, and the solidness
is in `alpha.png`, as for every `.16a`.

Not known: which font the game uses where.
